# Проект задач: архитектура Workspace

Статус: draft для согласования разбиения. Ни одна задача ниже не отмечена выполненной. Основная [спецификация](bb-architecture.md) описывает первый архитектурный этап.

Родитель архитектурных задач: [GitHub Issue #1](https://github.com/kornouhovas/workspace/issues/1). Очистка получит отдельную Issue, поскольку не входит в кодовый scope спецификации.

## 1. Управление вкладками и панелями через модель сессии

Blocked by: нет. До кодовой реализации сверить baseline с сохранёнными незавершёнными изменениями исходного checkout.

Результат: действия открытия/закрытия/reopen вкладок, split, focus, maximize/restore и возврат к Workspace/Settings идут через одного владельца состояния. Нынешний интерфейс сохраняется; существующие adapters восстановления работают на промежуточном шаге.

- [ ] Модель имеет явные команды и согласованный snapshot; React связывает их с прежними компонентами.
- [ ] DOM/platform эффекты остаются за границей чистой модели.
- [ ] Закрытие активной вкладки/панели выбирает прежний fallback; остальные панели сохраняются.
- [ ] Workspaces сохраняют отдельные вкладки и layout.
- [ ] Сохранение/восстановление продолжают работать; релевантные behavior tests, typecheck, renderer build и desktop проверка действий/геометрии завершены.

## 2. Восстановление и асинхронный предпросмотр через lifecycle сессии

Blocked by: задача 1.

Результат: перезапуск и переходы Workspace/view восстанавливают прежние вкладки, панели и preview через явный storage adapter; запоздалые ответы не меняют выбранный экран.

- [ ] Сохраняются ключи/версии session storage и чтение ранее сохранённых данных.
- [ ] Preview привязан к Workspace/view identity; ответ после нового выбора или закрытия отклоняется.
- [ ] Недоступный/повреждённый storage не блокирует работу; отсутствующий проект не оставляет пустую видимую оболочку.
- [ ] Сохранение/восстановление принадлежат session lifecycle; запросы идут через прежний сервисный клиент.
- [ ] Главный компонент использует snapshot/commands; CRUD и продуктовые очереди сохраняются.
- [ ] Restart/race checks, архитектурная проверка границы, программные проверки и Electron before/after на изолированных fixtures завершены.

## 3. Согласование и очистка документации

Blocked by: нет кодовых зависимостей. Удаление требует согласования конкретного списка и проверки ссылок; это отдельный scope от задач 1–2.

Результат: активные инструкции компактны и соответствуют принятым контрактам, история и доказательства сохраняются.

| Материал | Предложенное действие | Условие |
| --- | --- | --- |
| [AGENTS](../../AGENTS.md), [rules](../development/rules.md), [product](../development/product.md) | Согласовать устаревший запрет Status drag с ADR-007/008 | Сохранить разрешённые входные точки и безопасные операции |
| [quality gates](../workflow/quality-gates.md) | Сократить до ссылки на текущие проверки | Сохранить рабочий путь для входящих ссылок |
| [chat workflow](../workflow/codex-chat-workflow.md), [task lifecycle](../workflow/task-lifecycle.md), [review protocol](../workflow/review-agent-protocol.md), [Symphony readiness](../workflow/symphony-readiness.md) | Убрать старые обязательства из активного чтения, сохранить историю | Некоторые уже архивированы по статусу; проверить пользу дальнейших изменений |
| [Шаблоны](../templates/) | Выявить неиспользуемые шаблоны и сократить дубли | Проверить backlinks и документационные тесты до переноса/удаления |
| [Старые планы](../superpowers/plans/), [compact handoff](../design/compact-redesign-handoff.md), [matrix](../design/compact-edge-matrix.md), [review](../design/compact-implementation-review.md) | Отделить завершённую историю от действующих указателей | Сохранить provenance, evidence и ссылки незавершённых задач |
| [work](../../work/), [outputs](../../outputs/) | Инвентаризация завершённых run/fixtures и активных ссылок | Сохранять чужие untracked материалы и evidence незавершённой приёмки |
| [documentation test](../../test/documentation.test.js) | Уточнить обнаруживаемость после согласованной очистки | Сохранить полезную проверку лицензий и указателей |

Сохраняются актуальные продуктовые документы, модель данных, API, accepted ADR, security/лицензии и evidence незавершённых задач. Полный список удаляемых файлов формируется после backlink-проверки. В исходном checkout каталог `docs/superpowers` был удалён внешним действием во время подготовки; это удаление не входит в нашу ветку. Список выше составлен по её изолированному baseline и требует сверки перед применением.

- [ ] У каждого изменяемого пути есть причина, disposition и проверенные ссылки.
- [ ] Активные правила соответствуют продуктовым контрактам и accepted ADR.
- [ ] История сохранена; ссылки и профильный documentation check проходят.
- [ ] В коммит включены только согласованные изменения; `git diff --check` проходит.

## Отдельные последующие спецификации

Маркетинговый сайт по мотивам getbb.app, сервер/web/mobile, ИИ/skills/plugins и возможное подключение Go-хранилища не входят в задачи 1–3. Workspace — текущее рабочее название; позиционирование и материалы сайта ещё предстоит согласовать.
