# Domain docs

Workspace пока имеет одну предметную область. При анализе кода, формулировании спецификации и задач используйте [GLOSSARY.md](../../GLOSSARY.md), затем относящиеся к вопросу [ADR](../adr/) и [карту источников](../development/README.md).

Словарь определяет понятия продукта; детали runtime, транспорта и хранения принадлежат архитектуре и API-контрактам. Новое понятие записывайте после согласования его смысла. Читайте статус ADR: Proposed не является разрешением на реализацию. При конфликте с принятым ADR укажите конкретное расхождение и разрешайте только зависимую часть.

Для изменения модели используйте `domain-modeling`; для интервью с сохранением терминов и решений — `grill-with-docs`. Существующую структуру `docs/adr/` и её нумерацию сохраняйте. Новый ADR нужен для существенного компромисса с дорогим обратным изменением, а не для каждой задачи.
