# PRD: Workspace Project Board MVP

Актуальное уточнение: [ADR-006](adr/006-workspace-source-bindings.md) заменяет раннее предположение об общем источнике на независимые source bindings Workspaces. Действующий Electron использует JSON-адаптеры через preload IPC; `any-store` ниже описывает целевое хранение, а не подключение runtime. См. [карту архитектуры](development/architecture.md).

## Goal

Создать desktop-приложение, которое превращает выбранную пользователем папку с проектами в источник данных для Workspaces с Board и Table views, проектными properties и быстрым доступом к файлам проекта.

MVP должен позволить SMB-команде подключить существующую файловую структуру в Settings, создать один или несколько Workspaces поверх этой папки, увидеть проекты по статусам, управлять свойствами проектов и работать с проектной папкой без переноса данных в отдельную PM-систему.

## Background

Команды часто хранят проекты как папки на локальном диске, сетевом диске или в синхронизируемой директории. Такая структура удобна для файлов, но плохо подходит для обзора статусов, фильтрации, поиска и управления свойствами проектов.

Workspace Project Board должен дать Notion-like слой поверх существующих папок, сохраняя файловую систему как источник проектов. Локальные project metadata, views и properties должны храниться local-first через `any local` / локальный `any-store`, чтобы позже поверх этой модели можно было добавить `any sync`.

## Product Definitions

- Project source folder: общая папка проектов, выбранная пользователем в Settings.
- Workspace: сохранённая рабочая конфигурация поверх project source folder. Workspace хранит свои views, настройки отображения, фильтры по values и рабочие настройки properties.
- Project: папка, определённая как проект по правилам Workspace.
- View: сохранённый способ отображения проектов внутри Workspace, например Board или Table.
- Property: поле проекта, которое отображается в карточках, таблице и правой панели.
- Value: значение property для конкретного проекта или доступный вариант для select-property.
- Folder role: роль папки в дереве Workspace: `group`, `status` или `project`.

## MVP Scope

MVP включает:

- выбор project source folder в Settings;
- создание Workspaces в Left Panel поверх выбранной project source folder;
- сохранение списка Workspaces;
- удаление, переименование и перемещение Workspaces в списке;
- настройку дерева папок Workspace через роли `group`, `status`, `project`;
- поиск проектов внутри активного Workspace;
- Board view с группировкой проектов по статусам;
- Table view со строками проектов и выбранными properties;
- добавление и удаление views внутри Workspace;
- сохранение имени, типа, порядка и настроек properties для каждого view;
- выбор видимых values у properties в конкретном view для фильтрации проектов;
- правую панель проекта, открываемую из карточки или строки;
- отображение `Name`, `Status` и кастомных properties в панели проекта;
- отображение файловой структуры проекта в панели проекта;
- открытие файлов и переход в папки из панели проекта;
- базовые properties `Name` и `Status`;
- кастомные properties типов `text`, `number`, `single select`, `multi select`, `date`;
- добавление, удаление, изменение, перемещение и скрытие properties;
- добавление, удаление, изменение, перемещение и скрытие values у select-properties;
- история изменений properties и property values в local-first модели;
- local-first сохранение Workspace data через `any local` / `any-store`.

## Out Of Scope

В MVP не входят:

- авторизация;
- роли пользователей и права доступа;
- multi-user collaboration;
- пользовательская функция синхронизации через `any sync`;
- облачный backend как обязательная часть продукта;
- мобильное приложение;
- публичный web-доступ к Workspace;
- встроенный редактор файлов;
- полноценный таск-трекер с задачами, комментариями и исполнителями;
- интеграции с внешними PM-системами;
- импорт данных из Notion, Trello, Jira или других инструментов;
- автоматическая классификация проектов без настройки пользователем;
- произвольная файловая перестановка проектов вне явных Status-переносов. Ручной порядок строк Table сохраняется отдельно для view.

## User Stories

- Как пользователь, я хочу переключать интерфейс между English и Русский в Settings, чтобы работать на предпочитаемом языке без изменения данных проектов.
- Как пользователь, я хочу выбрать папку проектов в Settings, чтобы приложение использовало её как общий источник проектов.
- Как пользователь, я хочу создавать Workspaces поверх выбранной папки проектов, чтобы иметь разные рабочие конфигурации для одних и тех же проектов.
- Как пользователь, я хочу назначать папкам роли `group`, `status` и `project`, чтобы приложение правильно понимало мою структуру проектов.
- Как пользователь, я хочу видеть проекты на Board view по статусам, чтобы быстро понимать состояние работ.
- Как пользователь, я хочу видеть проекты в Table view, чтобы сравнивать свойства проектов в списке.
- Как пользователь, я хочу добавлять и удалять views, чтобы иметь разные способы просмотра одного Workspace.
- Как пользователь, я хочу выбирать, какие properties видны в конкретном view, чтобы не перегружать рабочую область.
- Как пользователь, я хочу выбирать, какие values у properties видны в конкретном view, чтобы фильтровать проекты.
- Как пользователь, я хочу настраивать ширину колонок отдельного Board view, чтобы выбрать удобную плотность карточек для текущего окна.
- Как пользователь, я хочу создавать кастомные properties, чтобы хранить важные для команды данные рядом с проектами.
- Как пользователь, я хочу редактировать property values у проекта, чтобы поддерживать актуальную информацию без отдельной таблицы.
- Как пользователь, я хочу открыть проектную карточку в правой панели, чтобы увидеть свойства и файлы проекта без ухода с основного экрана.
- Как пользователь, я хочу открывать файлы и папки проекта из приложения, чтобы быстро перейти к рабочим материалам.
- Как пользователь, я хочу искать проекты, чтобы находить нужную папку среди большого количества проектов.
- Как пользователь, я хочу, чтобы мои Workspaces, views и properties сохранялись локально, чтобы не настраивать их заново после перезапуска приложения.

## Functional Requirements

### Workspace Management

- Пользователь может выбрать project source folder в Settings.
- Каждый Workspace, созданный в Left Panel, использует выбранную project source folder.
- Пользователь может добавить новый Workspace без выбора отдельной корневой папки для него.
- Приложение сохраняет Workspace после добавления.
- Пользователь может переименовать Workspace.
- Пользователь может удалить Workspace из приложения без удаления файлов на диске.
- Пользователь может изменить порядок Workspaces в Left Panel.
- Приложение открывает последний активный Workspace после перезапуска, если он всё ещё доступен.

### Folder Role Configuration

- Settings показывает дерево папок внутри выбранной project source folder.
- Пользователь может назначить папке роль `group`, `status` или `project`.
- Папка с ролью `group` используется как контейнер; приложение ищет проекты внутри неё.
- Папка с ролью `status` задаёт статус проектам внутри неё и используется как колонка Board.
- Папка с ролью `project` считается проектом; приложение не ищет проекты глубже внутри этой папки.
- MVP поддерживает один уровень status folders; вложенные status-группы не поддерживаются.
- Изменение роли папки обновляет список проектов и их статусы в Board и Table.
- Приложение сохраняет роли папок локально для каждого Workspace.

### Project Discovery

- Приложение строит список проектов из дерева project source folder с учётом folder roles активного Workspace.
- Project `Name` по умолчанию соответствует имени проектной папки.
- Project `Status` в MVP определяется статусной папкой, в которой найден проект.
- Если проект найден вне папки с ролью `status`, его статус отображается как `No status`.
- Один и тот же проект не должен отображаться дублирующими карточками или строками.
- Проекты за пределами project source folder не отображаются.
- Проект должен идентифицироваться стабильным локальным id, а текущий относительный путь внутри project source folder должен храниться как locator. Абсолютный путь не должен быть primary id проекта.

### Views

- Workspace содержит один или несколько views.
- Пользователь может добавить Board view.
- Пользователь может добавить Table view.
- Пользователь может удалить view, если после удаления в Workspace остаётся хотя бы один view.
- Пользователь может переименовать view.
- Пользователь может изменить порядок views.
- Workspace сохраняет тип, имя, порядок и настройки каждого view.
- Настройки view включают отображаемые properties, порядок properties и скрытые properties.
- Настройки view включают видимые property values, которые используются для фильтрации проектов в этом view.
- Настройки view включают display-настройки properties, например `Wrap content` для `Text` колонок в Table view.
- Удаление view не удаляет проекты, properties или values.

### Board View

- Board view отображает проекты как карточки.
- Board view группирует карточки по `Status`.
- Каждая status-группа отображает название статуса.
- Карточка проекта отображает `Name` и выбранные для view properties. `Status` включён по умолчанию, но может быть скрыт в конкретном view.
- Board view скрывает проекты, чьи property values исключены настройками видимости values в этом view.
- Board view позволяет перетаскивать карточку в другую допустимую status-колонку через существующую операцию физического переноса.
- Клик по карточке открывает правую панель проекта.
- Board view обновляется после изменения folder roles, project properties или view settings.

### Table View

- Table view отображает проекты строками.
- Каждая строка отображает `Name` и выбранные для view properties. `Status` включён по умолчанию, но может быть скрыт в конкретном view.
- Пользователь может скрывать и показывать columns через настройки properties view.
- Для `Text` properties Table view по умолчанию показывает компактное однострочное значение; при редактировании такого компактного значения открывается всплывающий редактор по ширине ячейки, чтобы строка не увеличивалась. Пользователь может включить `Wrap content` в меню Text-колонки, чтобы текст переносился по ширине колонки, а высота строки увеличивалась под полный текст.
- Table view скрывает проекты, чьи property values исключены настройками видимости values в этом view.
- Клик по строке проекта открывает правую панель проекта.
- Table view обновляется после изменения folder roles, project properties или view settings.

### Project Detail Panel

- Правая панель открывается при выборе проекта в Board или Table.
- Заголовок панели показывает `Name`; таблица Properties показывает `Status` и кастомные properties проекта.
- `Status` в правой панели можно скрывать и показывать как panel-local настройку отображения; его системное значение остаётся derived из folder role и не меняется через property definition.
- Пользователь может редактировать values кастомных properties из панели.
- Панель показывает кастомные properties теми же типами и значениями, что используются в Board и Table.
- Изменение value в панели сразу обновляет текущий Board/Table projection без ручного refresh.
- Панель показывает файловую структуру выбранного проекта.
- Пользователь может открыть файл из панели проекта.
- Пользователь может перейти в папку из панели проекта.
- Панель закрывается без потери несохранённых изменений, если изменение property уже было применено.

### Properties

- Системные properties `Name` и `Status` доступны для каждого проекта.
- `Name` остаётся обязательной property в каждом view; `Status` является системной property, включается по умолчанию и может быть скрыт в конкретном view.
- Пользователь может переименовать display label системных properties `Name` и `Status` стандартными property menus; это не меняет их id, тип, derived values и системное поведение.
- Settings показывает только системную property `Status`, её derived values из folder roles и позволяет менять цвет точки у каждого status value.
- Settings не создаёт, не переименовывает, не удаляет, не скрывает и не перемещает кастомные properties.
- Кастомные properties и их values управляются из Table, Project Detail Panel, `Customize Columns` и property menus.
- Пользователь может создать кастомную property типа `Text`.
- Значения `Text` должны сохранять ручные переносы строк. В Table они отображаются компактно в одну строку, пока в настройках Text-колонки не включён `Wrap content`; компактное редактирование происходит во всплывающем редакторе без изменения высоты строки. В Project Detail Panel текст может отображаться и редактироваться как многострочное значение.
- Пользователь может создать кастомную property типа `Numbers`.
- Пользователь может вводить в `Numbers` plain number или простое арифметическое выражение с `=`, видеть вычисленный результат в закрытом состоянии и исходное выражение при повторном редактировании.
- Пользователь может создать кастомную property типа `Date`.
- Пользователь может создать кастомную property типа `Select`.
- Пользователь может создать кастомную property типа `Multi-select`.
- Пользователь может переименовать кастомную property.
- Пользователь может удалить кастомную property.
- Пользователь может изменить порядок properties.
- Пользователь может скрыть property в конкретном view без удаления самой property.
- Пользователь может показать ранее скрытую property в конкретном view.
- Пользователь может изменять значения кастомных properties в Project Detail Panel.
- Кастомные properties должны отображаться в Table как колонки активного view.
- Кастомные properties должны отображаться внутри карточки проекта на Board, если property включена в активном view.
- Кастомные properties должны отображаться в правой панели проекта независимо от текущего типа view, если они не удалены.
- Удаление property удаляет её values из product data после подтверждения пользователем.
- Приложение сохраняет историю изменений property definitions и property values в local-first модели.

### Select Values

- Для `single select` и `multi select` пользователь может создавать values.
- Пользователь может переименовать select value.
- Пользователь может удалить select value.
- Пользователь может изменить порядок select values.
- Пользователь может скрыть select value, если это поддерживается настройками отображения.
- Пользователь может выбрать, какие select values видны в конкретном view.
- Пользователь может назначать цвет select value.
- Удаление select value требует подтверждения, если value используется хотя бы одним проектом.
- Скрытые в конкретном view select values используются как фильтр: проекты с такими values не отображаются в этом view.
- `single select` допускает не больше одного выбранного value для проекта.
- `multi select` допускает несколько выбранных values для проекта.

### Search

- Search ищет проекты внутри активного Workspace.
- Search должен учитывать project `Name`.
- В MVP Search не учитывает property values.
- Результат поиска должен открывать найденный проект в текущем view или через правую панель.
- Пустой поисковый запрос возвращает обычное отображение активного view.

### Local Persistence

- Приложение сохраняет Workspaces, folder roles, views, properties и values локально.
- Данные сохраняются через `any local` / локальный `any-store`.
- Перезапуск приложения не должен сбрасывать Workspaces, views, roles, properties или values.
- История изменений properties и property values сохраняется локально как product data.
- Локальная модель хранения должна быть пригодна для будущего `any sync`.
- UI state, который не является product data, не должен смешиваться с Workspace product data.

### File-System Safety

- Приложение должно работать только внутри выбранной project source folder при обходе дерева проекта.
- Удаление Workspace из приложения не должно удалять папку или файлы на диске.
- Открытие файла или папки должно использовать безопасный путь внутри project source folder.
- Если project source folder недоступна, приложение должно показать понятное состояние ошибки.
- Если проектная папка была удалена или переименована вне приложения, приложение должно обновить отображение без падения.

## Edge Cases

- Project source folder пуста.
- Project source folder недоступна после перезапуска приложения.
- Пользователь удалил или переименовал папку проекта вне приложения.
- В дереве нет папок со статусной ролью.
- Проект найден вне папки со статусной ролью и должен попасть в `No status`.
- В статусной папке нет проектов.
- Одна папка ранее имела role `project`, но пользователь меняет её на `group` или `status`.
- Пользователь пытается удалить последний view в Workspace.
- Пользователь удаляет property, которая уже имеет values у проектов.
- Пользователь удаляет select value, который выбран в одном или нескольких проектах.
- Project name совпадает у нескольких папок в разных статусах.
- Путь содержит пробелы, Unicode-символы или символы, требующие экранирования.
- Поиск не находит проектов.
- Большой Workspace содержит много папок и файлов.

- Пользователь может создать Workspace поверх выбранной project source folder и увидеть его в Left Panel.

- Проекты вне папок с ролью `status` отображаются в группе `No status`.
- MVP поддерживает один уровень status folders.

- Пользователь может удалить view, если это не последний view Workspace.

- Workspace сохраняет настройки видимых property values в view и фильтрует проекты по ним.
- Пользователь может создать custom property каждого MVP-типа: `Text`, `Numbers`, `Date`, `Select`, `Multi-select`.
- Пользователь может добавлять, удалять, переименовывать, скрывать, показывать и переупорядочивать custom properties.
- Пользователь может добавлять, удалять, переименовывать, скрывать, показывать и переупорядочивать values у `Select` и `Multi-select`.
- Table отображает custom properties как колонки активного view.

- Workspaces, roles, views, properties, values и история изменений properties сохраняются локально через `any local` / `any-store`.

## Dependencies And Constraints

- Продукт работает с локальной файловой системой как источником проектов.
- Product data хранится local-first через `any local` / локальный `any-store`.
- Будущий `any sync` должен накладываться поверх local-first модели, а не заменять её.
- MVP не требует авторизации и облачного backend.
- Проект должен иметь стабильный локальный id как primary id; относительный путь внутри project source folder хранится как текущий locator.
- Любые изменения, которые затрагивают публичные contracts, data model или storage model, должны быть отражены в `docs/data-model.md`, API contracts и ADR на следующих этапах spec-first процесса.

## Risks

- Сложные или неоднородные структуры папок могут сделать автоматическое обнаружение проектов неоднозначным.
- Если product data привязать к нестабильному абсолютному пути, переименование или перемещение папок может привести к потере связи с properties.
- Большие деревья папок могут потребовать оптимизации сканирования и lazy loading.
- Удаление properties или select values может неожиданно удалить важные project metadata, если не будет подтверждения и понятного UX.
- Будущий sync-слой может быть сложнее добавить, если local data model будет смешана с UI-only state.

## Resolved Product Decisions

- Project source folder задаётся в Settings; Workspaces в Left Panel используют эту папку и являются разными сохранёнными рабочими конфигурациями поверх неё.
- Проекты лучше идентифицировать стабильным локальным id. Относительный путь внутри project source folder хранится как текущий locator; абсолютный путь не используется как primary id.
- Если проект найден вне папки с ролью `status`, он получает статус `No status`.
- MVP поддерживает один уровень status folders.
- Board позволяет перенос карточки в допустимую колонку Status; Table переносит проект за внутренний левый захват между явными Status-группами и сохраняет ручной порядок строк внутри группы.
- Search в MVP ищет только по project `Name`.
- История изменений properties и property values нужна в local-first модели.

### Explicit Status move

In preview/expanded Project Detail, selecting another existing derived Status explicitly moves the entire project folder to that status folder, preserving basename, project ID, properties/history and session. Current selection is a no-op. No status is unavailable unless an unambiguous physical target exists; the active runtime omits it from picker/drop choices while retaining derived groups and project access. A pending-only indicator beside Sidebar opens project/from/to/state details and disappears on success/error. Collisions, unsafe paths and metadata/filesystem failures preserve files and identity through tested recovery. Board cards and Table Status cells offer the same selection. Board drag targets a status column; Table drag starts only from its internal left handle, saves per-view row order, and changes Status only across explicit Status groups. See [Status move contract](api/workspace-status-move.md).
