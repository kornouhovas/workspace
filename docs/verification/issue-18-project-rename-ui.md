## Implemented interaction

An eligible active Table row opens an associated EN/RU Name input. Enter submits exact authored text; Escape/Cancel dismisses presentation and restores the initiating control or stable Table focus. WorkspaceServiceClient sends workspace/project IDs, an immutable operation UUID and current discovery revision. The service decides basename validity, same-parent containment, collisions, alias staging and recovery authorization. Retained rows keep exact Text editing while Name mutation is unavailable.

Committed Name remains separate from the draft and changes only through a current list reload after confirmation. Invalid/occupied/stale/unavailable results retain useful localized feedback and drafts without implying rollback. Pending submission blocks duplicates. Unknown outcomes retain operation identity independently of editor visibility and App backend/selection remounts; explicit status remains available through an authorized source sibling and despite unfinished-list errors. Refresh, cancellation, reconnect, rerender and list/status queries never replay rename/recovery.

Source-scoped unfinished lists load on mount/reconnect/relevant changes. Explicit review shows original/intermediate/destination placement states and only service-advertised `retry_original`, `finish_staged`, `complete_destination` and `keep_original` actions. Each recovery submits a fresh preview token after explicit action. Relevant revisions, observations, Refresh, operation/backend/selection changes invalidate previews and require another explicit review. Unknown recovery outcomes use the same operation's status. `kept_original` resolves as retained-original success; confirmed receipts reload current placement without optimistic Name replacement. Competing reassociation is disabled during rename editing/recovery. Staging locators/native identities are not exposed by these UI surfaces.
