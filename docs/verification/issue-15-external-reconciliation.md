## Matching and platform limits

[Architecture](../architecture.md#implemented-external-reconciliation-and-observation) records repeated complete scan/transaction validation, exact source/depth/exclusion/archive rules, category-before-project mapping and current/historical evidence conflicts. An unmatched active child defers its dependent category rename; retained child metadata is not inferred or deleted. An existing unavailable/conflicting category is not repaired from matching child evidence. No filesystem lock is provided, and indistinguishable reuse of the entire native tuple cannot be detected.

The implementation choices are informed by [Node 22.21.1 watch caveats](https://nodejs.org/download/release/v22.21.1/docs/api/fs.html#caveats), [Microsoft file information](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/ns-fileapi-by_handle_file_information) and [Microsoft filename rules](https://learn.microsoft.com/en-us/windows/win32/fileio/naming-a-file). Notifications/stat-time availability and native identity vary by platform/filesystem; IDs can be reused and case behavior has exceptions. These sources do not establish permanent or portable project identity. Missed hints require startup/Refresh fallbacks; degraded operation is visible. No schema reset or marker files are needed.
