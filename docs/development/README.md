# Документы разработки

Начните с [AGENTS.md](../../AGENTS.md): это обязательная точка входа в правила работы. Эта папка помогает найти нужный источник и не заменяет спецификации, контракты или принятые ADR.

## Порядок чтения

1. [Продукт](product.md) — что делает Workspace и где проходят границы MVP.
2. [Архитектура](architecture.md) — действующий runtime, слои и целевое хранение.
3. [Работа над задачей](workflow.md) и [проверки](quality.md) — реализация и завершение в рамках AGENTS.md.
4. [Дизайн](design/README.md) — существующие UI-источники и место для будущего документа пользователя.

## Источник по вопросу

| Вопрос | Обязательный источник |
| --- | --- |
| Правила работы, разрешения, ветки и коммиты | [AGENTS.md](../../AGENTS.md) |
| Продукт и границы | [PRD](../prd.md), [Vision](../vision.md), актуальные [сценарии](../flows/) |
| Слои и решения | [Архитектура](../architecture.md), [ADR](../adr/), особенно [ADR-006](../adr/006-workspace-source-bindings.md) |
| Данные и сервисные методы | [Модель данных](../data-model.md), [API-контракты](../api/) |
| Экраны и визуальные правила | [Interface](../interface.md), [UI guidelines](../ui-guidelines.md), [дизайн](design/README.md) |
| Проверки | [AGENTS.md](../../AGENTS.md), [quality gates](../workflow/quality-gates.md), команды [package.json](../../package.json) |

Для UI-задачи прочитайте Interface, UI guidelines и соответствующий flow; при вызовах сервиса — его API-контракт. Для backend/storage — архитектуру, модель данных, применимые принятые ADR и API. Для документации — затронутые источники и правила проверок документации.

Старые планы и отчёты дают контекст конкретной работы. Их процессные требования не выше AGENTS.md. Статус ADR проверяйте в самом документе: предложенное решение не считается принятым.
