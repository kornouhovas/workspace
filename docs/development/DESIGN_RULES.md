# Правила дизайна интерфейсов на основе bb

Этот документ задаёт переносимую систему UI и UX для прикладного веб-интерфейса в стиле bb. Он предназначен для разработчиков, дизайнеров и AI-агентов, которые будут строить другой продукт: от базовых токенов до форм, навигации, рабочих панелей и поведения в промежуточных состояниях.

**Визуальная цель:** спокойный, плотный рабочий интерфейс с ясной иерархией текста, почти монохромными поверхностями, небольшими радиусами, тонкими границами и цветом по смыслу. Важнее содержание и управление работой, чем декоративные блоки.

**Эталон:** get-bb/bb, commit `af72bb8167da292198bfa73b1c35ae3ac080bfca`. Документ подготовлен 30 сентября 2026 года по сохранённому снимку исходников. Это фиксированная спецификация, а не обещание совпадения с будущим `main`.

**Область:** веб-приложение `apps/app`, его Electron-представление, общие примитивы `packages/shared-ui`, связанные стили и UX. Мобильный раздел описывает адаптивный web UI; отдельное приложение Expo не является визуальным эталоном этого документа. Маркетинговый сайт также не входит в эталон.

**Точность:** численные значения, классы и поведение ниже извлечены из кода. Живое приложение в рамках этого разбора не запускалось; идентичность скриншотов и полное соответствие доступности не подтверждались. Там, где предлагается новая политика для принимающего проекта, стоит пометка **«Правило переноса»**. Наличие компонента в библиотеке не означает, что его базовый вид используется на каждом экране.

## Как пользоваться документом

1. Прочитать разделы о визуальном языке, токенах, типографике и плотности до создания страниц.
2. Подключить токены из приложения к документу. Идентичная версия вынесена в `bb-design-tokens.css` для удобства копирования.
3. Создать общие примитивы и состояния компонентов; только затем собирать экраны.
4. Применять паттерны bb к предметной области своего продукта. Термины «проект», «агент», «чат» и Git-функции не требуется переносить, если их нет в продукте.
5. Проверить результат по матрице приёмки. Для нового решения, которого нет в эталоне, определить компонентный контракт вместо случайных классов на одном экране.

**Приоритет при конфликте:** явное требование нового продукта → доступность и работоспособность → семантические токены → правила конкретного компонента → локальная композиция. Это правило переноса. Исключения должны быть осмысленными и повторно используемыми.

Слова **«обязательно»**, **«нельзя»** и **«использовать»** относятся к реализации по этой спецификации. Слова **«в bb»** описывают фактическую реализацию. Отдельно помеченные рекомендации не следует приписывать оригинальному проекту.

## Визуальный язык

### Основные признаки

- Фон и текст образуют две цветовые опоры. Большинство нейтральных поверхностей и границ вычисляется из них.
- В светлом режиме холст белый, основной текст тёмно-серый. В тёмном — глубокий графитовый холст и смягчённый светлый текст.
- Основная кнопка нейтральная: тёмная на светлой теме, светлая на тёмной. Синий не является универсальным брендовым цветом действий.
- Sidebar немного отличается от холста. Карточка и popover имеют тот же базовый цвет, что и холст; глубину создают граница и тень.
- Desktop-интерфейс плотный: подписи 12–13 px, основной текст 15 px, небольшие управляющие элементы. На узком сенсорном экране типографика и зоны нажатия увеличиваются.
- Интерфейс использует обычное и среднее начертание; полужирный текст отмечает иерархию, а не применяется ко всем подписям.
- Цветные акценты обозначают состояние, ссылку на файл, изменения кода, результат поиска или узнаваемую внешнюю сущность.
- Скругления сдержанные; капсулы предназначены для отдельных чипов и переключателей. Большой pill-радиус не применяется ко всем контейнерам.
- Действия появляются в контексте строки, панели или сообщения. Второстепенные команды размещаются в меню.

### Чего избегать при воспроизведении

Не превращать рабочие экраны в landing page с крупными hero-заголовками, широкими цветными секциями и декоративными градиентами. Не вводить независимые серые оттенки, не делать каждую область отдельной яркой карточкой, не заменять нейтральный primary произвольным насыщенным цветом. Градиенты в bb есть, но применяются локально: например, едва заметная поверхность mention-pill; это не общий фон приложения.

**Правило переноса:** один главный сценарий должен быть визуально очевиден в текущем контексте. Число primary-кнопок определяется конкуренцией действий, а не механическим ограничением «одна на весь экран».

## Технологическая основа

Эталон использует React, Tailwind CSS 4, `class-variance-authority`, `clsx`/`tailwind-merge`, Radix UI и собственные компоненты. Часть примитивов происходит из shadcn/ui, но стандартный внешний вид shadcn не равен стилю bb.

Radix отвечает преимущественно за поведение и семантику сложных элементов. Цвета, размеры, отступы и состояния определяет слой компонентов. Некоторые элементы реализованы без Radix: например, собственный `Switch` и адаптивный persistent drawer. Не заменять их стандартным компонентом и не считать результат автоматически эквивалентным.

Разделять:

- **Токены:** цвета, шрифты, радиусы, тени, размерный ритм.
- **Примитивы:** Button, Input, Menu, Dialog, Pill и другие компоненты, управляемые props.
- **Чистое представление сущностей:** строка объекта, статус, сообщение, блок результата.
- **Обвязку приложения:** данные, навигация, запросы, сохранение настроек, бизнес-правила.

Универсальный UI-примитив не должен зависеть от роутера, API, глобального хранилища или типов предметной области. Такое разделение закреплено в README UI-папки bb. [Границы UI компонентов](https://github.com/get-bb/bb/blob/af72bb8167da292198bfa73b1c35ae3ac080bfca/apps/app/src/components/ui/README.md)

## Система цвета

### Опорные цвета и основные текстовые роли

Все значения ниже — CSS OKLCH, не HSL. Формат `L C H` означает светлоту, цветность и тон.

| Токен | Светлая тема | Тёмная тема | Роль |
|---|---|---|---|
| `--canvas` | `oklch(1 0 0)` | `oklch(0.195 0 0)` | Холст |
| `--ink` | `oklch(0.3211 0 0)` | `oklch(0.81 0 0)` | Основной текст |
| `--background` | `var(--canvas)` | `var(--canvas)` | Фон страницы |
| `--foreground` | `var(--ink)` | `var(--ink)` | Основной текст |
| `--primary` | `oklch(0.27 0 0)` | `oklch(0.82 0 0)` | Основное действие |
| `--primary-foreground` | `oklch(1 0 0)` | `oklch(0.2178 0 0)` | Текст primary |
| `--muted-foreground` | `oklch(0.44 0 0)` | `oklch(0.78 0 0)` | Вторичная информация |
| `--readback-foreground` | `oklch(0.47 0 0)` | `oklch(0.715 0 0)` | Завершённые технические детали в истории |
| `--subtle-foreground` | `oklch(0.5 0 0)` | `oklch(0.68 0 0)` | Более тихие подписи |
| `--ring` | `var(--primary)` | `var(--primary)` | Клавиатурный фокус |

Не менять порядок визуальной значимости: foreground → muted → readback → subtle. У конкретного chrome-компонента может быть дополнительная прозрачность, но это не основание ослаблять весь вторичный текст. [Токены темы](https://github.com/get-bb/bb/blob/af72bb8167da292198bfa73b1c35ae3ac080bfca/apps/app/src/components/ui/theme.css)

### Производная нейтральная шкала

В таблице указана доля `ink`. Для непрозрачных поверхностей формула обычно `color-mix(in oklch, var(--ink) N%, var(--canvas))`. Для прозрачных состояний используется `oklab` и `transparent`.

| Роль | Light | Dark | Смешивание |
|---|---:|---:|---|
| `sidebar` | 2.2% | 4.3% | OKLCH с canvas |
| `secondary`, `accent` | 8% | 13% | OKLCH с canvas |
| `muted` | 11% | 16% | OKLCH с canvas |
| `border-seam` | 9.5% | 11% | OKLCH с canvas |
| `border` | 14% | 19.4% | OKLCH с canvas |
| `border-hairline` | 14.7% | 21% | OKLCH с canvas |
| `input` | 29.5% | 32.6% | OKLCH с canvas |
| `state-hover` | 5.9% | 13.8% | OKLab с transparent |
| `state-active` | 11.8% | 22.5% | OKLab с transparent |
| `surface-recessed` | 6% | 6% | OKLab с transparent |
| `surface-raised` | 2.5% | 2.5% | OKLab с transparent |
| `surface-recessed-solid` | 6% | 6% | OKLab с canvas |
| `surface-raised-solid` | 2.5% | 2.5% | OKLab с canvas |
| `surface-recessed-soft-solid` | 4.2% | 4.2% | OKLCH с canvas |
| `sidebar-accent` | 8% | 12% | OKLCH с canvas |
| `sidebar-border` | 14% | 18.1% | OKLCH с canvas |

`card = popover = background = canvas` в обеих темах. `surface-scrim` — `color-mix(in oklab, var(--canvas) 92%, transparent)`. Не путать этот световой scrim с затемняющим backdrop модального окна.

`border-seam` используется на границах оболочки: шапка, sidebar, разделённые панели. `border-seam-vertical` — alias, не отдельный оттенок. Токен `border-hairline` задаёт цвет, а не автоматически толщину 0.5 px.

**Обязательно:** использовать `bg-background`, `text-muted-foreground`, `border-border`, `bg-state-hover` и другие семантические роли вместо `bg-gray-*` или локальных hex. Нейтральные литералы допустимы в определении самой темы, а не как новые значения в компонентах.

**Важно:** не заменять OKLab на OKLCH в прозрачных смесях. В bb это проверяется тестами: выбор пространства влияет на итоговый цвет. Непрозрачные `*-solid` применяются там, где повторное наложение прозрачной заливки меняло бы тон. [Токены темы](https://github.com/get-bb/bb/blob/af72bb8167da292198bfa73b1c35ae3ac080bfca/apps/app/src/components/ui/theme.css), [Проверки темы](https://github.com/get-bb/bb/blob/af72bb8167da292198bfa73b1c35ae3ac080bfca/apps/app/src/components/ui/theme.test.ts)

Цвет успешного текста `success-foreground` получается смешиванием success 45% с ink. Синий `file-accent` является alias `timeline-accent`.

Не использовать цвет заливки destructive как универсальный цвет мелкого текста ошибки: в тёмной теме для текста определён более светлый `destructive-text`. В исходнике есть старые примитивы, которые ещё используют `text-destructive`; это не универсальная гарантия контраста. **Правило переноса:** для новых текстов ошибок использовать `destructive-text`.

Выделенные поверхности:

| Поверхность | Light | Dark |
|---|---|---|
| Ошибка | destructive 6% / transparent | destructive 8% / transparent |
| Граница ошибки | destructive 25% / transparent | destructive 30% / transparent |
| Требует внимания | attention 14% / transparent | attention 12% / transparent |
| Выбрано | primary 16% / transparent | primary 12% / transparent |
| Граница выбранного | primary 35% / transparent | primary 35% / transparent |

Все эти смеси выполняются в OKLab. Цвет состояния дополнять текстом, значком или структурой: один цвет не должен быть единственным способом понять состояние. Последнее — правило переноса, обязательное для доступной реализации.

### Темы и смена палитры

В bb режим `light / dark / system` и выбор палитры — разные настройки. Начальное предпочтение режима — system. Класс `.dark` устанавливается на корне; `color-scheme` должен соответствовать режиму. Предпочтение хранится локально; тема применяется до основного отображения, чтобы избежать вспышки другой палитры.

Кроме default в проекте есть Nord, Dracula, Solarized, Gruvbox и Catppuccin, а также custom CSS. Для точного воспроизведения базового вида этого документа использовать **default**, не подменять её произвольной «похожей» темой. Альтернативные палитры — необязательная возможность нового продукта, а не шесть обязательных дизайнов.

При добавлении палитры переопределять опоры, текстовые и семантические роли. Проверять отдельно overlay, terminal, code и diff: библиотечные поверхности не должны оставаться в старой теме. Порталы должны получать нужную тему даже вне DOM-поддерева панели. [Применение темы](https://github.com/get-bb/bb/blob/af72bb8167da292198bfa73b1c35ae3ac080bfca/apps/app/src/hooks/useTheme.ts)

## Типографика

### Шрифты

- Основной: `"Inter Variable", Inter, sans-serif`; в bb загружается пакет `@fontsource-variable/inter`.
- Моноширинный: `ui-monospace, SFMono-Regular, Menlo, Monaco, Consolas, "Liberation Mono", "Courier New", monospace`.
- Терминал: сначала `"JetBrainsMono Nerd Font Mono", "MesloLGS NF", "Symbols Nerd Font Mono"`, затем системный mono stack.
- Serif-токен: `Georgia, serif`; наличие токена не делает serif базовым стилем интерфейса.

Не заменять mono на Fira Code по старым исследовательским документам: в проверенном `theme.css` используется стек выше. Терминальные шрифты в стеке могут отсутствовать у пользователя; обязательна рабочая fallback-цепочка.

### Размерная шкала

Пересчёт rem в px ниже предполагает стандартный корневой размер 16 px. Не фиксировать root меньше 16 px ради плотности. Плотность задаётся токенами.

| Класс | Desktop и обычные условия | Узкий экран и coarse pointer |
|---|---|---|
| `text-2xs` | 10 / 14 px | 11 / 15 px |
| `text-xs` | 12 / 16 px, default Tailwind | 14 / 20 px |
| `text-sm` | 13 px; inherited ratio `1.25 / 0.875`, около 18.57 px | 15 / 22 px |
| `text-base` | 15 / 22 px | 16 / 24 px |
| `text-lg` | 18 / 28 px, default Tailwind | Не переопределён общей mobile-шкалой |
| `text-xl` | 20 / 28 px, default Tailwind | Не переопределён общей mobile-шкалой |
| `text-2xl` | 24 / 32 px, default Tailwind | Не переопределён общей mobile-шкалой |

Default line-height Tailwind 4.3.0 для text-sm — безразмерное отношение, поэтому изменение font-size до 13 px даёт около 18.57 px; явный `leading-5` по-прежнему 20 px. [Базовая типографика Tailwind 4.3.0](https://github.com/tailwindlabs/tailwindcss/blob/v4.3.0/packages/tailwindcss/theme.css#L318-L327)

Mobile-переопределение: `(max-width: 767px) and (pointer: coarse)`. Само по себе узкое окно мыши не получает эту увеличенную шкалу.

Компонент может явно задать `leading-5`, `leading-relaxed` или другой line-height; он имеет приоритет над типографическим default. Нельзя выводить высоту строки только из `text-sm`, если присутствует отдельный `leading-*`.

### Назначение текста

- `text-2xs` — счётчики, идентификаторы и мелкие технические маркеры. Не основной текст, не инструкции и не сообщения ошибки.
- `text-xs` — metadata, подписи инструментов, код, вспомогательные контролы.
- `text-sm` — основная плотная типографика UI и Markdown-сообщений.
- `text-base` — выделенный основной текст и небольшие заголовки содержимого.
- `font-normal` 400 — текст; `font-medium` 500 — подписи и действия; `font-semibold` 600 — заголовки и отдельные акценты.
- Базовый tracking 0em. Не вводить letter-spacing для всего интерфейса.

Токен chrome section label: `text-xs font-normal leading-5 text-subtle-foreground/75`. Это специальная приглушённая метка группы, не шаблон для длинных описаний.

**Обязательно:** пользоваться типографической шкалой и ролями. Не создавать случайные `text-[11px]`, `text-[14px]` в новых экранах. Размеры, уже определённые в компонентном контракте, фиксируются централизованно. Для 10 px текста не применять более слабый цвет, чем `subtle-foreground`; комментарий в теме специально ограничивает этот уровень. [Токены темы](https://github.com/get-bb/bb/blob/af72bb8167da292198bfa73b1c35ae3ac080bfca/apps/app/src/components/ui/theme.css), [Размерные и типографические контракты](https://github.com/get-bb/bb/blob/af72bb8167da292198bfa73b1c35ae3ac080bfca/packages/shared-ui/src/components/ui/coarse-pointer-sizing.ts)

## Геометрия и плотность

### Отступы

Базовая единица `--spacing: 0.25rem` = 4 px. Половинные шаги применяются в плотных компонентах.

| Tailwind | Значение | Типичное назначение |
|---|---:|---|
| `0.5` | 2 px | Микрозазор |
| `1` | 4 px | Внутренние интервалы чипов / меню |
| `1.5` | 6 px | Плотные подписи и меню |
| `2` | 8 px | Зазоры контролов, горизонтальный padding строки |
| `3` | 12 px | Padding компактных блоков |
| `4` | 16 px | Страница, карточка, диалог на узкой ширине |
| `6` | 24 px | Просторная карточка / группа |
| `8` | 32 px | Крупный интервал секций |

Назначения в последнем столбце — обобщение использования, не запрет других сочетаний. Не пытаться заменить все расстояния одним `gap-4`.

### Скругления

`--radius = 0.5rem` = 8 px. Семантические радиусы: sm = 4 px, md = 6 px, lg = 8 px, xl = 12 px. `rounded-full` оставлять для круглых значков, точек, аватаров, переключателей и подходящих pill-контролов. Размеры `rounded-2xl` и другие default Tailwind не пересчитываются автоматически из `--radius` в предоставленном файле.

### Границы и тени

Обычные разделители чаще 1 px; shell использует тихий seam. Не добавлять контрастную рамку вокруг каждой вложенной области. Focus ring — отдельное состояние, не постоянная вторая рамка.

Тени имеют характерную короткую нижнюю ступень. Например:

```css
/* light shadow-sm */
0px 2px 0px 0px hsl(0 0% 20% / 0.15),
0px 1px 2px -1px hsl(0 0% 20% / 0.15)

/* dark shadow-sm */
0px 2px 0px 0px hsl(0 0% 0% / 0.3),
0px 1px 2px -1px hsl(0 0% 0% / 0.4)
```

Для закреплённого снизу composer есть `shadow-lift`: `0 -4px 12px -4px`, light alpha .07 с 20%-серым, dark alpha .26 с чёрным. Полная шкала теней приведена в приложении. Не заменять её большими размытыми «парящими» тенями.

## Иконки и вспомогательная графика

Основной путь bb — общий `Icon`, основанный на Hugeicons. В теме есть `--icon-stroke-width: 1.75`, применяемый классом `.bb-icon-stroke` к явно подключившим его значкам. Общий Hugeicons-wrapper не назначает этот токен всем иконкам автоматически; сохранять родные glyphs и отдельные явно заданные stroke-правила. Иконки наследуют семантический цвет, не получают каждый свой серый оттенок.

Общая размерная сетка: 14 px для компактного значка, 16 px для обычного, 20 px для соответствующего узкого touch-представления. Размер иконки и зона нажатия — разные величины. Например, значок 16 px размещается в кнопке 28 px; на узком coarse pointer — 20 px в 36 px.

Кнопке без видимого текста нужны доступное имя и, на desktop, уместная подсказка. Декоративный SVG внутри подписанного элемента не должен повторно озвучивать ту же подпись. Не смешивать случайные наборы иконок на одном экране. В shared-ui встречаются Lucide-иконки в отдельных унаследованных компонентах; это факт реализации, а не рекомендация смешивать стили.

**Правило переноса:** логотип bb, названия провайдеров и внешние brand-иконки переносить только при наличии соответствующей функции; они не являются необходимой частью визуального языка.

### Высота и прокрутка

Оболочка web app использует `100dvh`; standalone-режим bb переключается на `100lvh` для особенностей iOS. Учитываются `env(safe-area-inset-*)`. HTML/body приложения не должны становиться вторым непреднамеренным scroll-контейнером. Прокручивается содержимое конкретной панели: `min-h-0 flex-1 overflow-auto`.

Не фиксировать composer поверх текста без компенсации и не допускать, чтобы мобильная клавиатура перекрывала основное действие. На root в bb подавлено вертикальное overscroll, но сохраняется нативный горизонтальный жест браузера назад/вперёд.

Обычный scrollbar тонкий: WebKit 8 px, thumb foreground 20% / transparent, hover 40%. Для лент и reading surfaces используется transient scrollbar; для двухосевых данных — persistent scrollbar 10 px с прозрачной рамкой 2 px. В короткой полосе вкладок scrollbar может быть скрыт при сохранении прокрутки.

Не сводить адаптацию к одной переменной `isMobile`. В bb независимы ширина viewport, coarse/fine pointer, hover capability, ширина панели, высота панели и наличие виртуальной клавиатуры.

## Кнопки и действия

Базовый Button: `inline-flex items-center justify-center gap-2 whitespace-nowrap rounded-md text-sm font-medium`. Focus-visible: ring 1 px цвета ring; disabled: opacity .5 и отсутствие pointer events. Иконка внутри — 16 px, не сжимается.

### Варианты

| Variant | Основной вид | Состояния |
|---|---|---|
| default | `bg-foreground text-background` | hover foreground/90 |
| destructive | destructive fill и destructive-foreground | hover fill/90 |
| outline | Прозрачный фон, border-input | hover state-hover |
| secondary | secondary / secondary-foreground | hover secondary/80 |
| ghost | Без постоянной заливки | hover state-hover; pressed или open — state-active |
| link | primary text | Подчёркивание при hover, offset 4 |

Важное различие: стандартный Button default в коде использует **foreground/background**, а не primary/primary-foreground. На нейтральной теме они близки, но не идентичны; на пользовательской палитре различие может быть заметным.

### Размеры

| Size | Высота | Padding-x | Текст |
|---|---:|---:|---|
| default | 36 px | 16 px | text-sm |
| sm | 32 px | 12 px | text-xs |
| lg | 40 px | 32 px | text-sm |
| icon | 36 × 36 px | По базовому контракту | Иконка |

Кнопка toolbar — отдельная обвязка: 28 px, padding-x 8 px, text-xs, border-border, прозрачный фон, без тени; touch 36 px.

SplitButton состоит из двух объединённых сегментов без двойной границы. Основное действие слева, раскрытие справа. Фокус должен оставаться видимым поверх соседнего сегмента. Меню выравнивается по правому краю.

**Правило переноса:** при асинхронном действии сохранять размер кнопки, обозначать занятость и исключать повторный запуск. Disabled с объяснением может оставаться фокусируемым через `aria-disabled`, но обработчик обязан блокировать действие. В bb такой паттерн есть у ResourceActionButton. Для обычного disabled без объяснения используется нативный disabled.

Не задавать native `title` на Button как замену Tooltip: в API Button bb этот prop исключён. Это ограничение конкретного компонента, а не запрет title на любом элементе. ## Меню и подсказки

### DropdownMenu

Desktop content: `z-50`, min-width 112 px, radius-md, border, popover surface, padding 4 px, shadow-md, offset 4 px. Строка: text-xs, gap 8 px, padding-x 8 px, padding-y 5 px, radius-sm; glyph 16 px. Нейтральное наведение — state-hover, открытое submenu — state-active. Destructive-пункт окрашен отдельно; disabled .5 и не принимает pointer events.

Labels: text-xs medium muted. Shortcut справа: text-xs, tracking-widest, opacity .6. Разделитель 1 px, вертикальный margin 4 px.

Последний наведённый пункт остаётся подсвеченным после ухода указателя. Клавиатурная навигация ArrowUp/Down, Home/End/PageUp/PageDown сбрасывает remembered hover, чтобы подсветка отражала focus. Строки меню не используют плавный hover.

На compact меню становится bottom drawer. Строки получают padding-y 8 px; класс остаётся text-xs, поэтому на coarse pointer он разрешается через mobile-типографику в 14 px. Не приписывать этому branch дополнительный переход на text-sm. Выбор закрывает меню, кроме случая `preventDefault`.

ContextMenu — родственный, но отдельный примитив: слой z70 и отсутствие собственного adaptive branch. [Меню](https://github.com/get-bb/bb/blob/af72bb8167da292198bfa73b1c35ae3ac080bfca/packages/shared-ui/src/components/ui/dropdown-menu.tsx)

### Tooltip и HoverCard

Tooltip: primary background / primary-foreground; radius-md; padding 12 ×6 px; text-xs; maximum `min(320px, available width)`; offset 4 px; collision padding 8 px. Переносить длинные слова. Показывать при keyboard focus, не провоцировать подсказку просто из-за pointer-induced focus.

У Tooltip нет единой заданной всеми компонентами задержки: provider проксирует Radix. У resource actions отдельно установлено 250 ms. **Правило переноса:** централизовать задержку для своего продукта, если требуется единая политика.

HoverCard default — width 256 px, padding 16 px, border, radius-md, popover surface, shadow-md. **Правило переноса:** существенная информация и единственный путь к действию не должны быть доступны только через hover. [Подсказки](https://github.com/get-bb/bb/blob/af72bb8167da292198bfa73b1c35ae3ac080bfca/packages/shared-ui/src/components/ui/tooltip.tsx)

Title text-base semibold leading-none tracking-tight. Description text-sm muted. Footer на узкой ширине column-reverse, с sm — row и выравнивание вправо, gap 8 px. Title/description связаны с aria-атрибутами.

На compact обычный Dialog использует responsive drawer; внутренние отступы left/right 16 px, top 8 px, bottom `max(16px, safe-area-bottom)`.

### Не смешивать разные реализации

| Компонент | Backdrop и поверхность | Отличие |
|---|---|---|
| Dialog | black/40, shadow-sm | Адаптивный wrapper |
| AlertDialog | black/80, shadow-lg, title text-lg | Отдельный Radix primitive; нет автоматического adaptive branch |
| Vaul Drawer | black/40, max-height 85dvh, rounded-t-xl | Низкоуровневый drawer; shouldScaleBackground=false |
| PersistentResponsiveDrawerShell | max-height `92dvh − keyboard inset`, rounded-t-xl | Общая оболочка адаптивных Popover/Menu/Dialog |

AlertDialog предназначен для сценария подтверждения; не использовать его просто как более тёмный обычный Dialog. **Правило переноса:** текст подтверждения называет действие и последствия, кнопка действия содержит глагол, отмена очевидна.

### Persistent responsive drawer

- Анимация 220 ms, `cubic-bezier(0.32,0.72,0,1)`.
- Drag area 64 ×32 px, handle 40 ×4 px.
- Закрытие после перемещения ≥25% высоты или скорости ≥450 px/s. Отменённый pointer drag не должен считаться завершённым закрытием.
- Click по backdrop закрывает по умолчанию.
- Escape и удержание Tab относятся к верхнему открытому drawer, с учётом вложенных overlays.
- У открытой панели role=dialog, aria-modal и доступное название. После закрытия фокус возвращается к подходящему существующему элементу.
- Закрытый сохранённый контент inert/aria-hidden. Нельзя для этой реализации помечать inert или aria-hidden корень всего приложения.
- Перекрытие клавиатурой от 80 px учитывается в bottom inset и max-height; pinch zoom не считать клавиатурой.
- Запускать transform до тяжёлого содержимого; реализовать его после двух animation frames с timeout fallback и далее сохранять mounted.

Не копировать только CSS drawer без управления фокусом, клавиатурой и retained content: внешний вид не воспроизведёт UX. [Диалоги](https://github.com/get-bb/bb/blob/af72bb8167da292198bfa73b1c35ae3ac080bfca/packages/shared-ui/src/components/ui/dialog.tsx), [Адаптивная overlay оболочка](https://github.com/get-bb/bb/blob/af72bb8167da292198bfa73b1c35ae3ac080bfca/packages/shared-ui/src/components/ui/responsive-overlay.tsx)

## Sidebar и навигация

Sidebar имеет собственный scroll-контейнер, группы, вложенные строки, sticky-контекст и footer. Строка: высота 28 px / 40 px на compact coarse pointer, radius-md, gap 8 px, text-sm; начальный левый inset 8 px, вложенность добавляет 24 px на уровень.

Отдельно отображать:

- текущий выбранный объект;
- объект, открытый в другой split-панели;
- непрочитанность;
- активную работу;
- результат или ошибку.

В bb «выбран» и «открыт в split» имеют разные классы и поверхности. Не сводить их к одному фону. Unread dot — 6 px / 8 px touch; рабочий статус может быть приглушённым, без насыщенной цветной заливки всей строки.

Inline rename: выбрать существующий текст, Enter сохраняет, Escape отменяет и возвращает focus; Enter с IME не сохраняет. Enter + blur не должны создавать двойное сохранение. При ошибке draft не теряется. Поздний ответ не должен перехватывать focus после перехода пользователя в другое место.

Размер и открытость sidebar сохраняются. Drag resize не должен запускать плавный transition ширины на каждом кадре. На compact открытие sidebar закрывает конфликтующую secondary shelf.

Если требуется воспроизвести жест открытия sidebar: browser edge protection 24 px, стартовая зона 72 px, распознавание намерения после 12 px; порог открытия 33%, fling от 12% при 450 px/s. Это специфичный жест bb, а не общее требование к любой боковой навигации. [Sidebar](https://github.com/get-bb/bb/blob/af72bb8167da292198bfa73b1c35ae3ac080bfca/apps/app/src/components/ui/sidebar.tsx)

## Composer и сценарии ввода

Этот раздел применяется к продуктам с чатом, командами или длинным вводом. Обычную форму не нужно превращать в composer.

Поверхность composer: width 100%, rounded-xl, border-border, bg-background, shadow-lift. Базовый min-height области редактора 68 px, а не всей карточки: header, toolbar и вложения добавляют высоту. В нераскрытом compact follow-up область ввода 48 px. Редактор имеет line-height 1.7; toolbar и контекстные настройки находятся рядом с вводом. Вложения — отдельные preview или pills с доступным удалением.

### Клавиатурное поведение

- Fine-pointer: Enter отправляет, Shift+Enter добавляет строку.
- Coarse-pointer: обычный Enter виртуальной клавиатуры вводит строку; аппаратный iPad Enter обрабатывается отдельно.
- IME: `isComposing`, keyCode 229 и событие после composition не должны случайно отправить текст.
- Если открыт typeahead: ArrowUp/Down меняют вариант, Enter/Tab сначала выбирают suggestion. Escape сначала закрывает typeahead.
- Ctrl/Meta+Enter может вызывать альтернативное действие, если оно определено; это не всегда «отправить».
- История ввода по ArrowUp/Down сохраняет текущий draft перед recall и возвращает его после выхода из истории.
- Focus не теряется из-за нажатия на collapse-control composer.

У активного агента bb различает queue и steer. Основное действие и modifier-action могут меняться настройкой; подсказка показывает обе команды. **Правило переноса:** если у продукта несколько способов отправки, назвать их по эффекту и показывать, какой именно сработает сейчас. Нельзя менять смысл Enter незаметно.

Вложения можно выбрать несколькими файлами или drag-and-drop. Preview изображения использует radius-md, border и recessed surface; file-pill может быть rounded-full, text-xs. В bb remove-target увеличивается с 16 до 28 px на compact coarse pointer; при переносе проверить реальную доступность этой цели.

Расположение composer и текстовой истории использует согласованную ширину. На низкой или узкой панели нераскрытый follow-up может использовать compact presentation; явно раскрытый, voice-active и `preferExpanded` режимы сохраняют свои правила. Раскрытие должно предшествовать редактированию, чтобы пользователь видел содержимое. [Composer](https://github.com/get-bb/bb/blob/af72bb8167da292198bfa73b1c35ae3ac080bfca/apps/app/src/components/promptbox/PromptBoxInternal.tsx)

## История сообщений и потоковая работа

Отделять пользовательский ввод, ответ, промежуточную работу инструмента и служебное состояние. Технические детали после завершения визуально отступают: для этого есть readback-foreground. File/timeline accent применяется дозированно, а не окрашивает весь ответ.

### Состояния

| Состояние | Представление и поведение |
|---|---|
| Первая загрузка | Skeleton структуры, не ложное empty state |
| История пуста | Осмысленное приглашение к началу или пустой контент по сценарию |
| Идёт работа | Локальный индикатор работы / thinking, потоковый контент |
| Требуется ответ пользователя | Явное взаимодействие с вопросом или решением |
| Ошибка загрузки | Отдельное сообщение об ошибке, возможность восстановиться |
| Потеря соединения | Отдельное состояние связи, не доказательство сбоя самой задачи |
| Остановка | Промежуточное состояние до подтверждённой остановки |
| Завершено | Итог и доступ к подробностям; контролы соответствуют фактическому состоянию |

Для истории bb задерживает начальный skeleton на 200 ms. Быстрый ответ не должен вызывать заметную вспышку заглушки. Прочитанный тестовый контракт требует сохранения позиции по видимой строке при добавлении старых сообщений и при возврате к чату.

### Прокрутка

- Если пользователь читает середину истории, новые сообщения не должны автоматически уводить его вниз.
- Если он оставил чат внизу, возвращение может восстанавливать нижний якорь.
- Подгрузка сверху не сдвигает текущий читаемый текст.
- Явная команда «вниз» отменяет отложенное восстановление старого якоря.
- Быстрый переход A → B → A возвращает контекст A.
- Показать affordance перехода к новым сообщениям, когда пользователь не у нижнего края.

Старые записи подгружаются sentinel-механизмом с резервной кнопкой. Не подменять это безусловным `scrollIntoView` после каждого рендера. [История и прокрутка](https://github.com/get-bb/bb/blob/af72bb8167da292198bfa73b1c35ae3ac080bfca/apps/app/src/components/thread/timeline/ThreadTimelineSurface.tsx)

### Подсветка синтаксиса

В Markdown используется отдельная code-only палитра. Идентификатор — foreground, знаки — muted, комментарии — subtle. Цветность ключевых слов и литералов умеренная.

| Токен кода | Light | Dark |
|---|---|---|
| keyword | `oklch(0.5 0.16 18)` | `oklch(0.74 0.14 18)` |
| string | `oklch(0.46 0.1 150)` | `oklch(0.78 0.12 150)` |

Встроенные diff-строки code block: добавление/удаление используют свои семантические цвета с прозрачностью 14% в OKLab; hunk — muted-foreground 8%, metadata — 4%. ## Файлы, diff и табличные данные

Файловая поверхность различает loading, empty, not-found, error, unsupported и конкретные preview-типы. Пустой файл — допустимый результат; отсутствие файла — другое состояние. Ошибка отображается с role=alert, содержит осмысленный текст.

Preview-header может быть sticky: внешняя поверхность sidebar, z10, внутренняя строка высотой 36 px, padding-x 16 px, gap 8 px, raised surface. Действия зависят от типа: копировать путь, обновить, переключить preview/raw, перенос строк. Не показывать неработающие команды ради одинакового toolbar.

Diff автоматически выбирает unified при ширине панели <760 px, split при ≥760 px, пока пользователь явно не выбрал режим. Compact стартует с unified; выбор compact не портит сохранённое desktop-предпочтение. Основа сравнения — **ширина панели**, а не монитора.

Библиотечный diff получает background, foreground, addition и deletion из общих токенов. Не оставлять жёсткие black/white + green/red значения в тёмной или custom-теме.

CSV-preview bb использует mono text-xs, leading-5, фиксированную таблицу со sticky header и номерами строк, высотой виртуальной строки 29 px. Колонка данных 18rem, номера 3rem; есть горизонтальный scroll. Ограничения 100 колонок / 500 строк и overscan 8 — технические настройки конкретного preview. **Правило переноса:** если вводятся подобные ограничения, показать явное сообщение об усечении; не скрывать данные молча.

ANSI-палитры light/dark и противоположный цвет текста для ANSI-фонов приведены в CSS-приложении. Терминал должен следовать активной теме приложения. [Файлы и diff](https://github.com/get-bb/bb/blob/af72bb8167da292198bfa73b1c35ae3ac080bfca/apps/app/src/components/secondary-panel/FilePreview.tsx)

## Загрузка, пустые состояния и ошибки

Эти состояния проектируются вместе с основным экраном.

| Состояние | Контракт |
|---|---|
| Loading | Skeleton повторяет структуру; сохранить основные размеры |
| Empty collection | Назвать отсутствие данных; добавить подходящее действие начала |
| No search results | Сохранить запрос и фильтры; предложить изменить их |
| Error | Конкретное сообщение и возможное восстановление |
| Not found | Явно отделить от временной загрузки |
| Unsupported | Объяснить, что нельзя отобразить; дать доступную альтернативу |
| Disabled | Предсказуемая причина; при необходимости доступное объяснение |
| Offline / reconnecting | Состояние связи отдельно от сохранённого содержимого |

Строки «No search results», offline и общее содержание сообщений в таблице — правила переноса, а не заданные тексты всех экранов bb.

Skeleton-примитив: `animate-pulse rounded-md bg-surface-selected`, размер задаёт потребитель. Resource loading default — 4 строки; skeleton aria-hidden, общий текст загрузки role=status. Resource error имеет role=alert и Retry outline/sm. EmptyStatePanel: dashed border, radius-md, padding 12 ×24 px, центрированный text-sm muted. Inline EmptyState: glyph 16 px, text-xs leading-5.

Не показывать empty до завершения первой загрузки, не сворачивать панель в нулевую высоту из-за отсутствия данных и не блокировать всю страницу из-за ошибки одной области. Последние требования — правила переноса. ## Движение и производительность восприятия

| Событие | Контракт bb |
|---|---|
| Hover обычного control | Появление сразу, уход 150 ms; `transition-colors duration-150 hover:duration-0` |
| Hover списка / меню | Без плавного перехода |
| Dialog desktop | 200 ms, fade и zoom95 |
| Panels / persistent drawers | 220 ms, cubic-bezier(.32,.72,0,1) |
| Footer follow-up composer | 180 ms, cubic-bezier(.16,1,.3,1) |
| Indeterminate progress | Цикл 1.5 s ease-in-out |
| Search result flash | 1.6 s ease-out |
| Accordion chevron | 200 ms |

Не применять `transition-all` ко всей оболочке. Resize по указателю должен следовать реальному положению, а не догонять его через 220 ms. При первом layout панель не должна анимировать переход из неверного начального размера.

Активная работа может иметь сдержанный shine. В bb это APNG-маска, чтобы уменьшить нагрузку на основной поток; скрытый контент освобождает mask/layer. Для переноса важен результат: индикатор не вызывает перерисовку всего большого списка и не продолжает бесполезную анимацию вне видимости.

`prefers-reduced-motion`: отключить sweep, декоративное движение, panel transitions и flash там, где это предусмотрено. Состояние остаётся понятным статически: например, indeterminate progress получает 50% ширины без движения. **Правило переноса:** проверить также primitives сторонних библиотек; наличие нескольких reduced-motion правил в проекте не доказывает, что любая анимация автоматически обработана. ## Доступность и управление фокусом

### Обязательные правила переноса

- Все действия доступны клавиатурой. Видимый keyboard focus обязателен; не удалять outline без равноценного ring.
- Accessible name соответствует действию. У icon-only кнопок есть aria-label; Tooltip не является единственной семантической подписью.
- Использовать нативные button/input и нужные роли. Clickable div не равен кнопке.
- Состояния open, selected, pressed, expanded, checked, invalid и busy отражаются соответствующими атрибутами.
- Порядок Tab следует визуальной задаче. Скрытая retained-панель не остаётся в tab order.
- Overlay получает имя; закрытие возвращает фокус, если исходная цель ещё существует и доступна.
- Не открывать виртуальную клавиатуру автоматически при каждом popover на touch.
- Hover-only controls имеют touch- и keyboard-путь.
- Сохранить выделение текста и нативное редактирование в input/textarea/contenteditable, даже если chrome-контейнер `select-none`.
- Цвет дополняется смыслом; текст не накладывается на фон с непроверенным контрастом.
- Проверить масштаб 200%, длинные строки, локализацию, высокую контрастность и screen reader. Это требования к принимающему проекту, а не заявление о прохождении таких проверок самим bb.

Тесты темы bb проверяют contrast ≥4.5 для readback, timeline-accent и destructive-text на базовом canvas. Это ограниченная проверка конкретных токенов. Она не гарантирует контраст текста с opacity .75/.5, любых custom palettes, цветных подложек или disabled-состояний. [Проверки темы](https://github.com/get-bb/bb/blob/af72bb8167da292198bfa73b1c35ae3ac080bfca/apps/app/src/components/ui/theme.test.ts)

## Технические правила реализации визуального слоя

1. **Единые токены.** Объявить их один раз; компоненты используют роли. Custom theme меняет систему, а не сотни локальных классов.
2. **Один размерный контракт на семейство.** Варианты Button, ToolbarAction и IconButton не должны случайно расходиться на разных экранах.
3. **Tailwind v4 source discovery.** Если компоненты лежат в workspace-пакете или node_modules, явно добавить подходящий `@source`; иначе классы могут исчезнуть из production CSS. Репозиторные пути bb в новый проект не копировать.
4. **Portal scope.** Портальный контент получает тему и доступное пространство; в Electron ему нужен `app-region: no-drag`.
5. **Слои.** В коде встречаются overlay z50, context menu z70, route progress z100, resize handle z25 и локальные sticky-слои. Это локальные значения, не готовая универсальная шкала для нового DOM. Проверить реальные stacking contexts и вложенные overlays.
6. **Не использовать CSS `@scope` для plugin UI.** В bb это запрещено из-за стоимости пересчёта WebKit; используются ограничивающие селекторы `:where(...)` с низкой специфичностью.
7. **Не размечать большой DOM глобальными `:has(*)` ради небольшого hover-эффекта.** Ограничивать selector конкретным контейнером и проверять стоимость на длинных списках.
8. **Сохранять mounted каркас адаптивных панелей.** Тяжёлое содержимое подключать после начала движения, а не блокировать начало анимации большим рендером.
9. **Проверять production bundle.** Tailwind purge/source discovery, подгрузка шрифта и portal CSS могут отличаться от dev.
10. **Stories для primitives.** Покрыть варианты и реальные состояния fixture-данными без сети. UX-сценарии тестировать отдельно от «снимка кнопки».

Пункты о разделении UI, source discovery, @scope и persistent drawers опираются на правила и реализацию bb. Конкретная организация файлов принимающего продукта может отличаться. [Границы UI компонентов](https://github.com/get-bb/bb/blob/af72bb8167da292198bfa73b1c35ae3ac080bfca/apps/app/src/components/ui/README.md), [Правила репозитория](https://github.com/get-bb/bb/blob/af72bb8167da292198bfa73b1c35ae3ac080bfca/AGENTS.md)

## Границы применения и новые сценарии

Документ охватывает базовый визуальный язык и основные семейства UI/UX веб-приложения bb. Он не утверждает, что каждый экран каждого plugin описан до пикселя. Доменные расширения наследуют систему, но могут иметь свои контракты.

Если новому продукту нужны карты, финансовые графики, сложный календарь, commerce checkout или совершенно иной доменный экран, исходники bb не задают для него исчерпывающий дизайн. **Правило переноса:** сначала определить задачи пользователя и доступность, затем выразить экран через эту систему цвета, текста, плотности и состояний. Отдельно утвердить семантические цвета данных и interaction model; не выдавать придуманные значения за извлечённые из bb.

Не переносить технические ограничения предметной области без смысла: названия провайдеров, лимиты CSV, Git-статусы, очередь сообщений и агентные режимы нужны только соответствующим функциям.

## Последовательность внедрения в другой проект

1. Подключить Inter, Tailwind 4, тему и базовые body-стили.
2. Реализовать light/dark/system и применение до первого отображения.
3. Создать gallery primitives: кнопки, поля, формы, меню, tooltip, dialog, drawer, список, карточка, toast.
4. Проверить gallery в обеих темах и в двух модальностях ввода.
5. Собрать shell и две характерные страницы: коллекция объектов и детали/форма. Добавлять split и composer, только если они нужны.
6. Реализовать loading/empty/error/disabled/selected/open для каждого рабочего сценария.
7. Подключить данные, сохранив чистый UI-слой.
8. Пройти матрицу приёмки; записать намеренные отклонения от эталона.

Это рекомендуемая последовательность переноса, не утверждение о порядке разработки самого bb.

Не добавлять `overflow:hidden` на body обычного сайта только ради совпадения с IDE: это правило конкретной full-viewport оболочки.

Принимающий проект должен пройти следующие проверки. Перечень является спецификацией приёмки, не отчётом о выполненных тестах.

| Область | Что проверить | Критерий |
|---|---|---|
| Цвет | Light/dark, default/custom при наличии | Нет случайных серых и библиотечных белых участков |
| Поверхности | Canvas, card, popover, sidebar | Верные роли; глубина не подменена цветными карточками |
| Типографика | 2xs/xs/sm/base, mono, длинные подписи | Нет случайных размеров, переполнений и пропавшего Inter |
| Desktop | 1440, 1024 и 768 px как тестовые ширины | Плотность и shell не ломаются |
| Compact | 767, 390 и 320 px как тестовые ширины | Drawer/overflow/текст доступны; нет горизонтального scroll всей страницы |
| Modality | Узкое окно с мышью, touch, широкий touch | Размер и представление зависят от правильной оси |
| Forms | Focus, filled, invalid, disabled, saving, server error | Подписи связаны, draft сохранён, ошибка рядом |
| Buttons | Hover, pressed, open, disabled, loading | Состояния различимы и не меняют геометрию неожиданно |
| Menus | Keyboard, pointer, submenu, disabled reason | Нет конфликтующего hover; выбор/закрытие предсказуемы |
| Overlay | Escape, Tab, outside click, вложенность | Работает верхний overlay; focus не теряется |
| Touch drawer | Drag, отменённый drag, клавиатура, safe area | Контент и действия не перекрыты |
| Lists | Длинный title, nested action, selected/unread | Нет двойного click и неоднозначного выбора |
| Loading | Быстрый и медленный ответ | Нет ложного empty и резкого схлопывания |
| Error | API error, offline, not-found | Различимый смысл и путь восстановления |
| Scroll | Новые элементы, prepend, A→B→A | Чтение не прерывается, якорь сохранён |
| Composer | Enter, Shift+Enter, IME, touch, suggestions | Нет случайной или двойной отправки |
| Content | Code, таблица, длинный URL, файл | Переполнение локальное и управляемое |
| Toast | Длинный текст, loading, действия | Уведомление не выходит за экран и не теряет важный текст |
| Motion | Reduced motion и resize | Нет обязательной декоративной анимации и задержки drag |
| Accessibility | Keyboard, screen reader, 200% zoom, contrast | Имена, роли, порядок, видимый focus, читаемость |
| Production | Собранная версия, шрифты, workspace CSS | Нужные классы и токены не удалены |

## Приложение с переносимым CSS

Ниже полное содержимое `bb-design-tokens.css`. Документ остаётся самодостаточным при копировании одного Markdown-файла. Значения `@theme`, light/dark и базовые правила извлечены из `theme.css`; удалены комментарии и репозиторные `@source`, добавлен импорт Inter. Компонентные стили, global app layout, анимационные assets и code-highlighting CSS сюда не включены: они описаны выше и реализуются отдельно.

Для сборки нужны Tailwind CSS 4, `tw-animate-css`, `@fontsource-variable/inter` и интеграция Tailwind с вашим bundler.
