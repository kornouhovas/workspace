# AGENTS.md

## Project Instructions

Before making any UI, UX, renderer, Electron app shell, navigation, layout, or component changes, read `styleguideline.md`.

Treat `styleguideline.md` as the source of truth for:

- UI and UX rules.
- Interface architecture.
- Visual style.
- Component reuse.
- Behavior.
- Terminology.

Do not invent a new component or pattern if an existing one is already described in `styleguideline.md`.

When a new stable component, pattern, state, restriction, or design rule appears during development, update `styleguideline.md`.

If a direct user instruction conflicts with `styleguideline.md`, follow the direct user instruction and then update the guideline if the change should become permanent.

After each completed user-requested action that changes project files, run the relevant verification and create a git commit for that action unless the user explicitly asks not to commit.
