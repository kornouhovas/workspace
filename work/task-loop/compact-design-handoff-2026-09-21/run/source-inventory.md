## Dangerous omissions to prevent
1. Treating all screenshots as Board only: Table and expanded card with simultaneous tab strips need concrete constraints.
2. Assuming toolbar visible on full/side-card state: actual code hides it while selectedProject != null. Any change is explicit interaction change.
3. Confusing duplicate PROJECT TAB with duplicate PROJECT or duplicate VIEW.
4. Removing hidden property section, system protections or option-level nested menus for visual simplicity.
5. Adding cross-status project drag/drop, New Project, upload, or editing folder-derived Status.
6. Interpreting no hover as removing keyboard focus feedback, accessible labels, native titlebar hit regions, or disabled styling.
7. Declaring all edge cases tested on code inspection. Runtime pixel clipping, native focus/drag, popover collisions, OS folder chooser and inaccessible files still require observed checks.
8. Fixed typography/density must be checked with Russian labels (often longer), empty states and 200% zoom. 200% is proposed acceptance, not claimed existing support.

## Suggested implementation acceptance inventory
Use an isolated fixture covering 0/1/many projects; 0/many statuses; status-less project; long Unicode names; all custom property types with empty and populated values; 20 views and 20 duplicate/mixed project tabs; 30 columns; deep file tree incl unavailable item. Matrix Board/Table × side panel/fullscreen/closed × sidebar open/closed at 1440x960 and 1024x720. Explicitly mark each row source-confirmed, runtime-observed, deferred native verification, or proposed design requirement. Avoid claiming exhaustive finite coverage of every possible combination.
